# Moyer Mail 方案设计

个人使用的多邮箱统一管理器。先做 Windows 桌面版，之后做安卓版。

## 1. 目标

**核心**
- 登录并管理多个邮箱：QQ、Gmail、Outlook/Hotmail、163/126、iCloud、雅虎、新浪、阿里邮箱、腾讯企业邮，以及任意支持 IMAP/SMTP 的邮箱。
- 统一收件箱：所有账号的邮件按时间合并显示，也可以单独看某个账号、某个文件夹。
- 统一发信：写信时选择用哪个账号发出；回复时自动用收到这封信的账号。

**不做**：自建域名邮箱、邮件服务器。

## 2. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 桌面外壳 | Electron 45 | 本机已有 Node，不需要装 C++ 编译器；Windows 11 原生磨砂（Mica/Acrylic）可用 |
| 界面 | React 19 + TypeScript + 纯 CSS | CSS `backdrop-filter` 做磨砂玻璃最灵活；这套界面安卓版可直接复用 |
| 收信 | imapflow | 成熟的 IMAP 库：IDLE 实时推送、OAuth2、代理、163 要求的 ID 命令都支持 |
| 发信 | nodemailer | 事实标准的 SMTP 库，支持 OAuth2 和代理 |
| 解析 | mailparser | 处理各种编码（GBK、Big5、ISO-2022-JP…）、内嵌图片、附件 |
| 本地数据库 | Node 内置 `node:sqlite`（含 FTS5 全文搜索） | 零原生依赖，打包简单 |
| 构建 | electron-vite + electron-builder | 开发热更新、打包成安装程序 |

### 架构

```
┌──────────────── 界面层（React，可复用到安卓）────────────────┐
│ 侧栏 │ 邮件列表（虚拟滚动） │ 阅读区（沙箱 iframe） │ 写信浮层 │
└───────────────────────────┬──────────────────────────────────┘
                            │  MailApi（请求/响应 + 事件推送）
┌───────────────────────────┴──────────────────────────────────┐
│ 宿主层：Electron 主进程（窗口、托盘、通知、密码加密）          │
│ 安卓版将来换成 Capacitor + nodejs-mobile，引擎原样复用          │
├──────────────────────────────────────────────────────────────┤
│ 引擎层 core（纯 Node，不依赖 Electron）                        │
│  账号管理 │ 同步器(IMAP+IDLE) │ 发信(SMTP) │ OAuth │ 翻译 │ 存储 │
└──────────────────────────────────────────────────────────────┘
```

界面只通过 `MailApi` 这一个接口和引擎通信，引擎不直接依赖 Electron（宿主能力通过注入提供），这样安卓版只需要换宿主层。

## 3. 各邮箱接入方式

| 服务商 | 收信 IMAP | 发信 SMTP | 登录方式 | 注意 |
|---|---|---|---|---|
| QQ 邮箱 | imap.qq.com:993 | smtp.qq.com:465 | **授权码** | 网页版 设置→账号 里开启 IMAP/SMTP 后生成授权码 |
| 163 / 126 / yeah | imap.163.com 等 | smtp.163.com 等 | **授权码** | 必须发送 IMAP ID 命令，否则报“Unsafe Login”，已处理 |
| Gmail | imap.gmail.com:993 | smtp.gmail.com:465 | **应用专用密码**（需开两步验证） | 大陆网络需要代理，软件内置代理设置 |
| Outlook / Hotmail | outlook.office365.com:993 | smtp-mail.outlook.com:587 | **OAuth2**（微软已停用密码登录） | 需要一次性配置微软应用 ID，见第 8 节 |
| iCloud | imap.mail.me.com:993 | smtp.mail.me.com:587 | 应用专用密码 | |
| 雅虎 | imap.mail.yahoo.com:993 | smtp.mail.yahoo.com:465 | 应用专用密码 | |
| 新浪 / 阿里 / 腾讯企业邮 | 预置 | 预置 | 密码或授权码 | |
| 其他 | 手动填写 | 手动填写 | 密码 | |

添加账号时只需选服务商、填邮箱和授权码，服务器参数自动带出；选“其他”时才需要手填。

## 4. 功能清单

### 第一批（本次实现）
- 账号：添加（服务商预设 + 连接测试）、编辑、删除、每个账号的颜色标记与签名。
- 收信：
  - 首次同步每个文件夹最近 300 封的信头，最新 60 封预下载正文，打开即显示。
  - 收件箱保持 IMAP IDLE 长连接，新邮件秒级到达；其他文件夹定时轮询。
  - 增量同步：只拉新 UID、批量对比旗标、检测服务器端删除。
- 视图：全部收件箱、未读、星标、已发送（跨账号汇总）；每个账号的文件夹树。
- 阅读：HTML 邮件在无脚本沙箱中渲染，内嵌图片、附件列表（打开/另存为），可选是否自动加载远程图片（防追踪）。
- 操作：已读/未读、星标、删除（移到废纸篓）、归档、移动；界面立即响应，后台同步到服务器，失败自动回滚并提示。
- 写信：新邮件 / 回复 / 全部回复 / 转发，选择发件账号，附件（可拖入），简易富文本，收件人自动补全，草稿自动保存在本地。
- 搜索：本地全文搜索（主题、发件人、正文），输入即出结果。
- 翻译（见第 6 节）。
- 系统集成：新邮件桌面通知（点击直达该邮件）、托盘图标与未读数、关闭时最小化到托盘、开机自启（可选）。
- 设置：主题色、浅色/深色、代理、翻译服务、同步间隔、通知。

### 第二批（下一步）
- 邮件会话（按主题串联）
- 定时发送、稍后提醒（Snooze）
- 服务器端搜索（搜本地没缓存的旧邮件）
- 规则/过滤器、邮件模板
- Gmail 标签、Outlook 分类
- 列表中显示翻译后的标题

### 第三批
- 安卓版
- 多设备设置同步（导出/导入配置文件）
- AI 摘要、AI 帮写回复

## 5. 界面与交互

**风格**：简约实用 + 磨砂玻璃 + 纯色背景。
- 窗口底色是一个纯色（可选：雾蓝、薄荷、暖杏、樱粉、石墨、深夜 等），底色上有两三团同色系的柔和光斑，让玻璃面板的磨砂效果看得出来。
- 侧栏、列表、阅读区是三块半透明磨砂面板：`backdrop-filter: blur(28px) saturate(160%)`，细白描边，大圆角。
- 无边框窗口，自绘标题栏，Windows 关闭/最小化按钮保留系统原生样式。
- 浅色/深色/跟随系统。

**速度（重点）**
- 所有数据先从本地数据库读，网络在后台跑：点开邮件 = 读本地缓存，不等网络。
- 已读、星标、删除等操作“先改界面、后同步”。
- 写信、设置、添加账号都是浮层，点击即出，动画 ≤120ms，没有任何“加载中”遮罩。
- 按钮按下有即时的缩放与高亮反馈（`:active` 立刻生效，不等过渡）。
- 邮件列表虚拟滚动，几万封也流畅。
- 键盘快捷键：`J/K` 上下封、`C` 写信、`R` 回复、`A` 全部回复、`F` 转发、`S` 星标、`U` 标为未读、`E` 归档、`Delete` 删除、`T` 翻译、`/` 搜索、`Esc` 关闭浮层。

## 6. 翻译

**场景**
1. 读信翻译：阅读区一个“翻译”按钮（快捷键 `T`）。保留原邮件排版，只替换文字；随时切回原文。可设为“非中文邮件自动翻译”。
2. 写信翻译：用中文写，一键翻译成英文/日文/韩文/法文/德文/西班牙文/俄文等；回复时自动选成对方邮件的语言。翻译结果可以替换正文，或附在原文下方（中外文对照）。
3. 划词翻译：在邮件里选中一段文字，弹出小气泡显示译文。

**翻译服务（可切换）**
| 服务 | 费用 | 说明 |
|---|---|---|
| Google 翻译（免费接口） | 免费、免配置 | 默认。一次请求翻译多段并保留排版，自动识别 100+ 种语言；大陆网络需要代理 |
| 微软翻译（Azure 官方接口） | 每月 200 万字符免费 | 国内直连，需要在 Azure 申请密钥（F0 免费层） |
| 大模型（OpenAI 兼容接口） | 按量付费 | DeepSeek、通义千问、Kimi、OpenAI 等，填 Base URL + Key + 模型名；质量最好，语气自然 |
| DeepL | 免费额度 50 万字/月 | 需要 API Key |

翻译结果按“文本+目标语言”缓存在本地，同一封信再打开不重复请求。

## 7. 数据与安全
- 所有数据只存在本机：`%APPDATA%\Moyer Mail\`。
- 授权码 / 密码 / OAuth 令牌用 Windows DPAPI（Electron `safeStorage`）加密后存储，不落明文。
- 邮件 HTML 先用 DOMPurify 清洗，再放进禁止脚本的沙箱 iframe；链接一律用系统浏览器打开。
- 界面进程开启 contextIsolation + sandbox，没有 Node 权限。

## 8. Outlook 的 OAuth 配置（一次性）

微软已经停止 Outlook.com 的密码登录，第三方客户端必须走 OAuth2，需要一个“应用 ID”：
1. 用微软账号登录 <https://entra.microsoft.com> → 应用注册 → 新注册。
2. 支持的账户类型选“任何组织目录中的帐户和个人 Microsoft 帐户”。
3. 重定向 URI 选“公共客户端/本机(移动和桌面)”，填 `http://localhost`。
4. 复制“应用程序(客户端) ID”，粘贴到 Moyer Mail 设置 → 账号登录 → 微软应用 ID。
之后添加 Outlook 账号时点“用微软账号登录”，在浏览器里授权即可。Gmail 也支持同样的 OAuth 方式（可选），但用应用专用密码更简单。

## 9. 安卓路线
- 界面层（React）原样复用，布局已按窄屏做了响应式（单栏 + 页面切换）。
- 方案 A（首选）：Capacitor 承载界面 + nodejs-mobile 运行同一份 core 引擎。
- 方案 B：如果需要更省电的后台推送，改用原生 Kotlin 写同步服务，界面不变。
- 需要安装：JDK 17、Android SDK（届时自动安装）。

## 10. 目录结构
```
src/
  shared/      类型定义、服务商预设、MailApi 接口（界面与引擎共用）
  core/        引擎：db、accounts、sync、send、oauth、translate、proxy
  main/        Electron 宿主：窗口、托盘、通知、IPC
  preload/     把 MailApi 暴露给界面
  renderer/    React 界面
scripts/       图标生成等脚本
docs/          文档
```
